مشروع متجر BRITTON — بريتون
تصميم أسود وأحمر فاخر، واجهة عربية RTL، متجر ولوحة إدارة منفصلان داخل المشروع.

الملفات:
- index.html + style.css + main.js : واجهة المتجر.
- admin.html + admin.css + admin.js : لوحة التحكم.
- firebase-config.js : إعدادات Firebase الحالية.
- firestore.rules و storage.rules : قواعد حماية قاعدة البيانات والصور.

مهم: المشروع واجهة تشغيلية أولية مرتبطة بـ Firebase. يجب إكمال خطوات الإعداد التالية قبل النشر.

1) رفع الملفات
- فك ضغط BRITTON_STORE_PACKAGE.zip.
- ارفع جميع الملفات الموجودة داخله إلى جذر المستودع في GitHub (نفس مكان index.html).
- لا ترفع مجلد BRITTON_STORE_PACKAGE نفسه داخل المستودع؛ ارفع الملفات التي بداخله.
- فعّل GitHub Pages من Settings > Pages > Deploy from a branch > main > /(root).
- المتجر يفتح من رابط GitHub Pages المعتاد.
- لوحة الإدارة تفتح بإضافة /admin.html إلى نهاية رابط المتجر.

2) تفعيل Firebase
- افتح https://console.firebase.google.com/
- اختر المشروع britton-life-store.
- من Build فعّل Firestore Database وأنشئ قاعدة بيانات.
- من Build > Authentication > Sign-in method فعّل Email/Password.
- من Authentication > Users أضف مستخدماً للمدير ببريدك وكلمة مرور قوية.
- افتح المستخدم وانسخ User UID.
- في Firestore > Rules الصق محتوى firestore.rules، واستبدل PASTE_ADMIN_UID_HERE بـ UID الحقيقي، ثم Publish.
- في Storage فعّل الخدمة، ثم Rules الصق storage.rules واستبدل PASTE_ADMIN_UID_HERE بنفس UID، ثم Publish.

3) إعداد رقم واتساب
- افتح firebase-config.js.
- في storeWhatsApp اكتب رقم واتساب المتجر بالأرقام الدولية فقط دون + أو مسافات. مثال توضيحي لليمن: 9677XXXXXXXX.
- احفظ الملف وارفعه إلى GitHub مرة أخرى.

4) الاستخدام
- افتح /admin.html وسجّل الدخول ببريد المدير وكلمة المرور التي أنشأتها في Firebase.
- أضف المنتجات والأسعار والقسم والمخزون والوصف، ويمكن رفع حتى 3 صور للمنتج.
- الطلبات الجديدة تحفظ في Firestore وتظهر في لوحة الإدارة.
- المنتجات النشطة فقط تظهر في واجهة المتجر.
- الطلبات تحفظ في قاعدة البيانات، ثم يفتح واتساب إذا أضفت الرقم في الإعدادات.

تنبيهات أمان مهمة:
- لا تضع كلمة مرور المدير في أي ملف من ملفات الموقع.
- إعدادات Firebase الظاهرة في المتصفح ليست بديلاً عن قواعد Firestore وStorage؛ لا تنشر قبل استبدال UID ونشر القواعد.
- لا تضع PASTE_ADMIN_UID_HERE كما هو؛ يجب استبداله بالـ UID الحقيقي.
- راجع الطلبات وبيانات العملاء في Firebase ولا تشارك صلاحية المدير.
- الدفع المعروض حالياً هو طلب/دفع عند الاستلام بالتنسيق مع العميل؛ لا توجد بوابة دفع إلكترونية مدمجة.
- الإحصائيات الحالية مبنية على بيانات الطلبات المسجلة، ولا يوجد عداد زوار تحليلي مفعل في هذه النسخة.
